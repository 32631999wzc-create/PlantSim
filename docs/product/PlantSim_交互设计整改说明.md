# PlantSim 交互设计整改说明

实施日期：2026-10-23。沿用现有 Clay 视觉规范及离线数据快照，不引入外部组件库或 API。

## A. 需求理解

目标是减少业务打断、保护输入并提高连续处理效率，而不是增加弹出层。整改覆盖企业采购、养护、资料查询，以及原模拟流程中的详情、趋势分析、编辑与重置。原有 Gate、版本隔离及公开事实边界不变。

## B. 组件选型

| 场景 | 采用方式 | 理由 | 不采用方式 |
| --- | --- | --- | --- |
| 采购计划、现场复核、其他编辑 | 桌面右侧 Drawer；小屏全屏编辑 | 保留原页上下文，自动暂存输入 | 默认居中 Modal |
| 工单、批次、来源详情 | Drawer，保留上一层返回；工单/批次可切换相邻记录 | 连续核对证据 | 重复关闭、打开嵌套弹窗 |
| 常用名称 | 行内展开，原按钮再次点击收起 | 低风险辅助信息 | 遮罩弹窗 |
| 价值趋势、费用分析 | 独立页内分析空间，返回原业务页 | 持续探索，保留原页状态 | 大型分析弹窗 |
| 撤回采购草稿 | 直接执行，Toast 撤销及列表恢复入口 | 可恢复、低风险 | 强制二次确认 |
| 重置当前会话 | 有未归档内容时使用强确认 | 明确数据损失后果，允许导出备份 | 无提示重置 |
| 放弃未提交草稿 | 编辑区内就近确认 | 避免再叠加一个模态层 | 再次默认弹窗 |
| 评审结论确认、恢复 Gate | 保留必要的集中决策/恢复交互 | 重要业务步骤 | 为减少弹窗而移除风险保护 |

Drawer 使用原生 dialog 的焦点约束与 Escape 事件，右侧布局保留主页面可见上下文；它不允许绕过未完成编辑去操作背景。移动端改为全屏。没有将简单说明机械地改成 Drawer。

## C. 交互流程

### 采购

缺苗事项 → 打开编辑 → 恢复该项目、该物料的未提交内容 → 修改数量/供应商/到货日期 → 显示估算货款、计划未覆盖量和超期警告 → 保存本地采购草稿 → 清理未提交草稿 → 返回采购台账。

- 暂存不代表保存业务记录，更不代表下单、锁货或新增在途。
- 计划到货晚于进场日期时持续提醒，但允许保存计划目标，不把它当作供应商承诺。
- “计划尚未覆盖”只是计划测算；实际缺口不因草稿减少。
- 撤回后10秒内可通过 Toast 撤销，也可以之后通过列表恢复；恢复时校验重复草稿。

### 复核

待办 → 查看原发现 → 填写复核日期与现场说明 → 选择后续状态 → 保存追加记录。

“复核动作已完成”与“问题已解决”分开：继续观察、转专业鉴定仍保留待办；问题已处理才移除待办。原始只读工单不变。历史记录缺少后续状态时，保守保留待办，不能据旧“已完成复核”推断问题解决。

### 查询与证据

查询植物 → 常用名称行内查看 → 点击供苗/养护入口时携带植物筛选 → 明示当前筛选并支持清除。企业台账始终标注为独立演示项目，不自动冒充当前模拟项目的真实 ERP 资料。

详情打开来源后可返回上一层，不丢失原详情。分析空间有明确返回按钮；趋势周期切换在分析空间内完成。

## D. 异常与边界

- 未提交编辑以独立 `plantsim.interaction.drafts.v1` 存储，按项目、业务类型、对象隔离，不修改发布快照。
- 输入自动暂存；关闭、Escape 再次尝试暂存。读写失败时不声称保存成功、不静默覆盖损坏草稿；未能暂存时阻止关闭，允许继续编辑、导出填写备份或明确放弃。
- 已提交业务与未提交填写是两层数据；业务保存失败保留输入；业务保存成功但清理旧草稿失败时给出持续警告。
- 原主页面的目标、环境、任务卡等字段在当前会话跨页返回时恢复；刷新/离开未归档会话时注册浏览器离开保护。浏览器提示受用户交互和浏览器策略限制，不等同于项目自动持久化。
- 企业编辑草稿可刷新恢复，但清除站点存储仍会丢失，不跨设备同步。
- 工作备份 JSON 包含当前项目、当前编辑与本地登记，用于留存材料；本轮未提供任意备份文件的导入恢复功能，不将下载备份称为项目归档。
- 校验错误内联呈现；原生字段校验关联错误说明，错误字段获得焦点。业务错误保留在编辑区；可恢复反馈使用 Toast，须处理的异常使用持续提示。
- 重复提交防护、正整数、真实日期、有效报价、同项目同苗木重复草稿等校验保留。

## E. 前端实现

- `plantsim-interaction.js`：未提交草稿存取与隔离键。
- `plantsim-interaction-ui.js`：统一选型、Drawer、编辑保护、返回栈、分析空间、筛选衔接、风险确认和可访问性。
- `plantsim-interaction.css`：沿用 Clay 的暖白、薄边框、圆角和克制阴影，窄屏全屏编辑。
- `plantsim-operations.js`：撤回恢复、后续状态校验与待办计算。
- `plantsim-workspace-ui.js`：业务表单和列表接入。
- `tools/sync-enterprise.cjs`：生成自包含的四脚本离线 HTML，维护源码与交付文件同步。

## F. 验收

```sh
node tools/sync-enterprise.cjs .
node --test *.test.js
# 先启动指向 plantsim-demo.html 的独立、干净 Edge CDP 配置，再运行：
node tools/qa-workspace.cjs <port> <screenshot-directory>
node tools/qa-interaction.cjs <port> <screenshot-directory>
```

专项检查：编辑焦点、Tab 约束、Escape/关闭恢复、刷新恢复、明确放弃、模拟存储失败、估价及超期提醒、撤回撤销与列表恢复、复核/问题分离、来源返回、相邻记录切换、行内名称说明、带对象跳转、分析返回、风险重置、移动端提交。布局检查覆盖2560、1920、1278、1024、768、390像素。验收不以“页面没有溢出”替代业务流程验证。

本次不接入 API；公开资料、演示台账、未提交草稿和本地已登记记录保持边界。
