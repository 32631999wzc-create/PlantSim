# PlantSim 前端页面规划文档 V1.1

> 基于 PRD V1.0 + 技术开发文档 V1.0 的深度分析，对现有 7 页描述进行业务闭环补全、排版规划和任务拆解。
> 设计风格：Clay（有机暖色黏土风）| 日期：2026-09-03 | V1.1 更新：用户审核后定稿

***

## 一、现有页面描述的问题诊断

### 1.1 现有 7 页（PRD Table 10）

| 页面      | 核心内容                             | 关键动作          |
| ------- | -------------------------------- | ------------- |
| 1 项目方案  | 项目、植物清单、场地、位置、设计版本               | 导入资料 / 生成基线   |
| 2 模拟目标  | 自然语言目标与结构化理解                     | 确认 / 多轮补充     |
| 3 未来蓝图  | 蓝图、路径、因素关系、任务卡参数                 | 编辑路径 / 开始模拟   |
| 4 模拟运行  | 时间轴、各节点状态、异常恢复                   | 查看进度 / 展开运行详情 |
| 5 结果与风险 | 地图、时间线、风险卡、养护结果                  | 定位问题 / 追问原因   |
| 6 方案比较  | 原方案与优化方案跨未来比较                    | 修改 / 重新模拟     |
| 7 运行记录  | Trace、Gate、Tool、Retry、Checkpoint | 回看节点 / 专家模式回溯 |

### 1.2 诊断出的核心问题

**问题 A：业务流未闭环——缺少项目入口**

用户从哪里开始？PRD 流程从"导入项目资料"起，但没有"项目列表/工作台"页面。用户需要先创建或打开项目才能进入页面 1。缺少项目级入口会导致：

- 无法管理多个项目

- 无法在项目间切换

- 首次使用无引导

**问题 B：业务流未闭环——多轮对话无统一承载面**

PRD 4.2 明确提到"多轮对话"，在两处需要：

- 页面 2 模拟目标（目标确认与补充）

- 页面 5 结果与风险（追问"第 20 个月为什么这样"）

但两处对话都嵌在业务页面中，没有定义统一的会话面板组件，会导致：

- 交互模式不一致

- 上下文绑定逻辑（session\_id/run\_id/path\_id/plant\_id/cycle）重复实现

- 指代表达解析（"刚才那 3 棵树"）无法复用

**问题 C：业务流未闭环——"调整→重跑→比较"循环路径断裂**

核心业务价值之一是"修改可验证"。完整路径应为：

```
结果与风险(P5) → 发现问题 → 修改设计方案 → 重新模拟(回P4) → 新结果 → 方案比较(P6)
```

但现有页面线性排列 P5→P6→P7，没有体现这条循环回路。用户从 P5 到 P6 再回到 P4 的导航路径缺失。

**问题 D：业务流未闭环——专家评测入口缺失**

PRD 7-8 节和 API `POST /evaluations` 都提到专家评测和 Bad Case 标记，但没有对应的前端入口。应该在 P7 运行记录中集成，但现有描述未提及。

**问题 E：页面排版未规划——每页仅一行描述**

7 个页面各只有一行内容描述，没有：

- 页面布局结构（分区、网格、侧栏）

- 组件清单与类型

- 信息层级与优先级

- 页面间共享组件定义

- 响应式策略

直接开发会导致各页面风格不统一、信息密度失控、频繁返工。

**问题 F：设计版本管理面缺位**

PRD 4.6 提到 Design Version V1 → V2，技术文档数据模型也包含 `Project → DesignVersion → SimulationSession`，但没有页面明确承载版本管理。版本管理应分布在 P1（创建/编辑）和 P6（比较），但现有描述未覆盖。

**问题 G：模拟运行状态转换不清晰**

P4 模拟运行是异步后台任务。模拟完成后用户从哪里进入 P5？是自动跳转还是用户手动导航？运行中异常恢复的用户通知机制也未定义。

## 二、页面架构规划（闭环补全）

### 2.1 页面清单（7 → 8 页 + 1 共享组件）

| 编号 | 页面    | PRD 对应 | 状态 | 核心职责                    |
| -- | ----- | ------ | -- | ----------------------- |
| P0 | 项目工作台 | **新增** | 新增 | 项目列表、创建、入口导航            |
| P1 | 项目方案  | 原页面 1  | 增强 | 资料导入、基线生成、设计版本管理        |
| P2 | 模拟目标  | 原页面 2  | 增强 | 目标输入、结构化确认、多轮对话         |
| P3 | 未来蓝图  | 原页面 3  | 增强 | 蓝图可视化、路径拆解、任务卡编辑        |
| P4 | 模拟运行  | 原页面 4  | 增强 | 并行进度、周期时间线、异常恢复         |
| P5 | 结果与风险 | 原页面 5  | 增强 | 风险地图、时间线、原因链、追问         |
| P6 | 方案比较  | 原页面 6  | 增强 | 版本选择、多维比较、跨未来对比         |
| P7 | 运行记录  | 原页面 7  | 增强 | Trace 树、Gate/Retry、专家回溯 |
| —  | 会话面板  | **新增** | 新增 | 共享组件，P2/P5 复用           |

### 2.2 闭环导航流

```
P0 项目工作台
  │  [新建项目] / [打开项目]
  ▼
P1 项目方案 ◄──────────────────────────┐
  │  [基线就绪 → 设置目标]              │
  ▼                                     │ [修改设计方案]
P2 模拟目标                              │
  │  [目标确认 → 生成蓝图]              │
  ▼                                     │
P3 未来蓝图                              │
  │  [任务卡冻结 → 启动模拟]            │
  ▼                                     │
P4 模拟运行                              │
  │  [模拟完成 → 查看结果]   ┌──────────┘
  ▼                         │
P5 结果与风险                │
  │  [发现问题 → 追问]       │
  │  [决定修改方案]──────────┘
  │  [需要回溯]
  ▼
P6 方案比较 ◄── [修改 → 重跑 → 回 P4]
  │  [需要技术回溯]
  ▼
P7 运行记录
  │  [专家审核 / 标记 Bad Case / 节点重放]
  ▼
（闭环：专家决策 → 回 P0 归档或回 P1 新版本）
```

**`ModifySchemeModal`** **统一修改方案组件定义**：

三处修改方案入口（P1 主动修改、P5 发现问题后修改、P6 比较后修改）使用完全相同的弹窗组件，确保用户在任何位置触发修改方案的体验一致。

```

│  修改设计方案                     [×]    │
├─────────────────────────────────────────┤
│                                         │
│  基于版本: V1 (当前版本)                 │
│  新版本号: V3 (自动递增)                 │
│                                         │
│  修改说明:                               │
│  ┌─────────────────────────────────┐    │
│  │ textarea                        │    │

│  │  调整A14位置间距至2.5m,         │    │
│  │  增加滨水区灌溉设施..."          │    │
│  └─────────────────────────────────┘    │
│                                         │
│  修改内容预览:                           │
│  ┌─────────────────────────────────┐    │
│  │ 植物 A12: 秋枫 → 火焰木 (替换)    │    │
│  │ 植物 A14: 位置调整 (x:12→x:15)  │    │
│  │ 新增设施: 滨水区滴灌系统           │    │
```

三处入口行为：

- P1：左侧栏"新版本"按钮 → 打开 ModifySchemeModal → 提交后留在 P1 编辑新版本

- P5：底部"修改方案"按钮 → 打开 ModifySchemeModal → 提交后跳转 P1 编辑新版本

- P6：底部"修改方案"按钮 → 打开 ModifySchemeModal → 提交后跳转 P1 编辑新版本

- 顶部导航栏右侧药丸式 toggle：`[专家] [普通]`

- 专家模式选中技术节点（如 Gate）→ 切换普通模式 → 自动定位到包含该节点的 Cycle 原因链

## 十、已确认决定

以下 8 项决策已由用户审核确认，作为实现的最终依据：

1. **P0 项目工作台** — 不精简，保持完整工作台：Hero + 数据统计概览（6 色统计卡）+ 项目卡网格 + 平台能力展示 + 3D Footer
2. **会话面板共享** — 认可共享底层逻辑+子组件（消息格式/上下文绑定/Trace 取证/指代解析/版本管理），P2 为右侧固定栏，P5 为底部浮动抽屉
3. **P5 结果页 Tab** — 合并为 4 个 Tab（地图/时间线/风险卡/养护），原因链作为风险卡的就地展开态，不独立成 Tab
4. **P6 方案比较** — 支持最多 3 版本同时比较。新增 VersionSelector 多选组件（checkbox 卡片，最少 2 最多 3，达到上限未选项禁用）。矩阵/地图/图表均动态支持 2-3 列
5. **P7 双模式** — 专家模式和普通模式同时实现，顶部药丸 toggle 随时切换。专家模式显示完整 Trace（Tool/Gate/Effect/State/Model/Prompt/Checkpoint），普通模式只显示简化原因链。切换不丢失节点位置
6. **Demo 案例数据** — 使用华南滨水公园案例并增加方案复杂度（见第十一章）
7. **设计版本管理** — P1 左侧栏版本列表 + P6 版本比较 + 三处修改方案入口（P1/P5/P6）使用统一 ModifySchemeModal 组件，UI 和排版完全一致
8. **P4 异常处理** — 仅业务约束错误（Gate 阻断：Schema/Spatial/Numeric/Business）弹出 Modal + 动态步骤条。工具调用错误/模型错误静默自动恢复，事件流 muted 色记录。恢复成功后顶部 Toast 提示
