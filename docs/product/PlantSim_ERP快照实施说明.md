# PlantSim 企业知识协同 · 离线快照实施说明

版本：2026-10-22 / enterprise-2026-10-22-v1

## 1. 本轮范围

按已确认的园林企业通用ERP业务规划实施。运行时不调用ERP API、物种API、联网搜索或大模型；全部资料、实体、记录、规则和页面内嵌于 plantsim-demo.html。外部原文仅在用户主动点击链接后打开。

沿用已选定的 Clay 设计规范与现有宽屏响应式规则。公开项目不是当前模拟项目，新增企业演示项目有独立编号；没有把公共公告的中标方编造为苗木供应商。

## 2. 页面信息架构

原有项目工作台及八个设计验证步骤保持不变，步骤页脚仍按1—8计数。侧栏使用独立暖赭色“企业协同”收缩分组；设计主流程中默认收起，进入企业页面时展开，支持再次收起。移动端通过“企业协同”菜单进入四个栏目。

| 页面 | 职责 | 可用交互 |
| --- | --- | --- |
| 工作概览 | 按业务影响安排待办 | 缺苗优先、待复核次之，直接进入采购或复核表单 |
| 苗木采购 | 从需求到采购计划 | 供苗缺口、有效报价、本地草稿登记与撤回；批次/历史报价折叠查阅 |
| 养护管理 | 待办处理与工作留痕 | 待复核工单优先，本地复核追加登记，公开案例次级折叠 |
| 资料查询 | 快速查资料与业务记录 | 搜索框置顶、最新答案优先、历史查询及出处折叠，支持俗名确认和规格选择 |

本体与关系映射只作为底层检索能力保留，不再作为独立页面。前台使用“常用名称”“苗木规格”“库存批次”等业务术语，不展示系统集成演练或技术关系图。

企业查询页不混入项目的线性“下一步”。项目页面通过轻量协同卡进入查询；结果页携带当前选中植物发问。原目标对话中的库存、供应商、报价、别名、工单和ERP问题可转入统一查询。

## 4. 领域对象与检索规则

物种/名称组、规格物料、库存批次、项目、供应商、工单和模拟对象分别建模，使用明确关系连接。

- 三角梅/簕杜鹃/叶子花/九重葛定位贸易名称组；大叶紫与金心双色是不同演示物料，先确认规格再计算缺口。
- 扶桑定位朱槿；名称识别不自动改变原植物清单或模拟参数。
- 红蜘蛛返回叶螨类群与柑橘语境候选，用户确认的是查询范围，不是物种鉴定。
- 腻虫定位蚜虫类群，可返回上海公开排查报道；不将农作物植保资料外推为当前园林现场事实。
- “这种植物”“刚才那家”复用明确的会话实体；没有前文对象时要求补充。更换实体清除旧规格和供应商，更换项目清除会话。
- 未命中问题不生成无出处答案。已知实体但没有库存记录时，不写成库存为零。

离线检索支持列出的查询类型与内置词表，不承诺任意自然语言理解。更新词表、记录或规则后通过重新发布快照生效。

## 5. 业务口径

- 可用库存 = 现存 − 预留 − 隔离。在途始终单列，只有预计日期不晚于项目期限才参与期限内缺口。
- 所有“下月”与交期提示均以2026-10-22快照和演示项目的交付日期解释，不冒充今天的实时结果。
- 报价显示规格、税和运费口径、有效期；已过期报价保留历史标识。
- 预算、已发生、尚未转为实际的承诺、完工预测分别展示，完工预测不能与实际再次累加。
- 公开公告金额不参与现有模拟成本或五维评分。
- 资料引用进入目标草稿，必须经过现有业务Gate确认；只引用名称和来源，不自动修改参数。
- 创建运行时深拷贝当前引用与资料版本；新引用不会修改已有运行。

## 6. 本地登记与异常边界

采购计划与复核记录使用独立的浏览器 localStorage，不修改只读快照，也不向外部系统提交。采购数量校验为正整数，排除过期报价，防止同项目同物料重复草稿；撤回保留记录。计划到货时间是用户目标，不是供应商承诺。采购草稿不抵扣缺口。

复核记录只能关联当前演示项目的原工单，不能改写公开报道。“继续观察”仍保留待办；“已完成复核”清除对应待办，但不改变原工单状态、不推断物种和用药。日期与现场说明必填。存储失败明确报错，不假装保存成功；损坏数据不静默覆盖。

本地登记仅在当前浏览器、当前站点可见，不跨设备同步。清除站点存储会丢失登记。原有底层缺源与访问视角测试保留，但不作为业务导航或生产权限功能暴露。

## 7. 维护方式

- plantsim-enterprise.js：只读快照、名称映射、实体关系、库存与查询计算。
- plantsim-enterprise-ui.js：检索、来源、引用及原流程衔接。
- plantsim-workspace-ui.js：四个任务导向业务页面、收缩导航与办理表单。
- plantsim-operations.js：本地采购草稿、复核记录、校验和持久化；不修改快照。
- plantsim-enterprise.css / plantsim-workspace.css：查询组件与业务工作区样式。
- tools/sync-enterprise.cjs：将以上文件同步到原UI、展示样式及离线HTML，保留四个内嵌脚本包。
- plantsim-enterprise.test.js：业务和数据关系测试。
- plantsim-operations.test.js：采购、复核、持久化与业务隔离测试。
- tools/qa-workspace.cjs：当前四个业务页面的端到端验收入口；旧 qa-enterprise.cjs 已退役，不再对应页面导航。

```bash
node tools/sync-enterprise.cjs .
node --test *.test.js
```

首次同步后仍需执行现有源码嵌入同步测试。不要直接只改HTML而遗漏维护源码。

## 8. 本阶段完成与后续

本阶段实现任务优先工作台、采购与复核本地登记、可交互快照、公开证据、名称确认及项目引用。后续如补充更多物种、供应记录或真实履约材料，沿相同来源字段扩展；当前没有API接入任务，也没有自动提交采购订单或养护工单。
